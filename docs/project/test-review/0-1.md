## 1. Guarantee

Every endpoint active behind the gateway corresponds to an operation of the OpenAPI specification. An undocumented
endpoint (a "shadow API") escapes review, rate limiting and authentication policies (OWASP API9:2023 Improper
Inventory Management).

- **A PASS promises:** no undocumented path found with the lists used, no undeclared method handled on the
  documented paths, no undocumented version found next to the documented ones, and (with the gateway) no route
  without a documented path under it.
- **It does not promise:** that no other undocumented path exists (fuzzing covers the lists, not every path); that
  a documented endpoint is safe (authentication 1.1, authorization 2.1, content 6.4).
- **Only this question.** 0.1 reports that something exists outside the specification. Whether it requires a
  credential is 1.1; whether a user without the role reaches it is 2.1; whether it shows credentials is 6.4;
  whether the gateway forwards paths it has no route for is 0.2; whether a documented deprecated version is
  switched off is 0.3; whether two versions enforce the same controls is 2.4.

## 3. Inputs

- **Specification:** the paths and their methods (`AttackSurface`), the parameter types (sibling patterns, piece 3),
  the specification's own URL (not a shadow path).
- **Derived knowledge** (Phase 2): `service_prefixes` (piece 7); a new rule `version_siblings` (HEURISTIC), added
  with this test: for each documented path with a version segment (`VERSION_SEGMENT`: `v1`, `v2.7`), the same
  path with the neighbouring versions not documented for it: per version position (the path before the version
  segment), the major numbers from 1 to the highest plus one that are not documented. Derived (2026-10-21): Forgejo
  `/api/v2`; crAPI `/identity/api/v1` and `v3`, `/identity/api/auth/v1` and `v5`, `/community/api/v1` and `v3`;
  whether they answer is seen in the 0.1 runs (rule 5).
- **Gateway** (optional): the `routes` concept (`GatewayRoute`: name, paths, methods, backend, enabled), already read
  by both adapters.
- **Configuration:** `target.path_seed` (values for parameters, the resources the operator declares usable by
  tests); new parameters in section 11.
- **Lists** (for ffuf): SecLists `Discovery/Web-Content/common-api-endpoints-mazen160.txt` (174 API words, placed
  under each base path) and `Discovery/Web-Content/api/api-endpoints.txt` (285 paths at release 2026.1, tried from the root), pinned to
  release 2026.1 by `install_tools.sh`; the sensitive-path catalogue of the tool (`src/core/sensitive_paths.py`, 35
  suffixes such as `actuator/env`, `.env`, `debug/pprof/`, each with its source; one catalogue for 0.1 and 6.4, topic 7b);
  the user's list (`wordlist`), optional.

## 4. Preconditions and reference responses

- **Calibration** (rule 3): an undocumented path is judged against random siblings under its parent
  (`ReferenceResponses.same_as_unknown`): it exists when it answers unlike them (`Existence` PROVEN or INDICATED).
  A point whose two random answers differ is not used: `NOT_VERIFIABLE/CALIBRATION_UNSTABLE`.
- **Unsupported method reference:** for `undeclared_methods`, what the API answers for a method it does not
  support on that path; the expected answer is `405` or `501` (`METHOD_NOT_ALLOWED`); a target that answers
  otherwise (a framework that gives `404` for any unmatched method) is calibrated with a method no API implements.
  **To verify on the labs** which answer each lab gives.
- **No positive control:** every request is unauthenticated except where a credential is needed to tell existence;
  0.1 does not judge authentication.

## 5. Probes

- **`ext.0.1.ffuf`:** ffuf, unauthenticated `GET`, at `external_tools.ffuf.rate_limit_rps` (default 30), **one run
  per base path** with ffuf's own calibration (`-ac`) to drop the obvious "not found" answers (one run over several
  base paths calibrates once: on crAPI 627 of 836 answers kept, because identity answers 401 with 49 bytes, community
  404 with 19, workshop 404 with 179 to any unknown path; one run per base path kept 1); base paths: each derived service prefix and each
  documented version directory under it (crAPI `/identity/api/v2/`, `/identity/api/v3/`, ...), plus the root for the
  full-path list. Order of size: about 2,500 requests on crAPI, fewer on Forgejo (**to verify on the labs**). Each
  candidate ffuf returns that matches no documented path template (`/repos/{owner}/{repo}` matches
  `/repos/a/b`), is not the parent of documented paths (`/identity/api/auth` above `/identity/api/auth/login`;
  `/api` above Forgejo's paths) and is not the specification's URL is requested again by the test with the tool's client and judged
  with the calibration: ffuf proposes, the test proves.
- **`0.1` `undeclared_methods`:** for each documented path, each method of `GET`, `POST`, `PUT`, `PATCH`, `DELETE`
  the specification does not declare for it (`HEAD` is implied by `GET`, RFC 9110 §9.3.2; `OPTIONS` is sent once
  per path and only its `Allow` header is reported):
  - parametric path: on a random identifier that does not exist (sibling pattern, typed values): a handled method
    finds nothing to act on; on the `path_seed` values when the operator declared them;
  - non-parametric path: the path itself, with an empty JSON body for `POST`, `PUT`, `PATCH`;
  - a request that creates something (`2xx` with `Location`, or a `PUT` on a random identifier accepted) is cleaned
    up with `DELETE` where possible, otherwise stated in the result as left on the target (owner, 2026-10-21).
- **`0.1` `undocumented_versions`:** for each version group (prefix and version), a sample by a stated rule: one
  documented `GET` path per group without parameters, or with the `path_seed` values; the same path with each
  sibling version, unauthenticated, judged with the calibration under the sibling's parent.
- **`0.1` `gateway_route_drift`:** no request to the API: the gateway's routes read through the adapter.

## 6. Oracle

**`undocumented_paths`** (`ext.0.1.ffuf`):

| Case | Outcome / detail | Confidence |
|---|---|---|
| candidate answers unlike the calibration (any category except `NOT_FOUND`-like answers equal to the unknown sibling) | `VIOLATION/UNDOCUMENTED_PATH` | FIRM (it exists; it may be harmless) |
| candidate answers like an unknown path | `NOT_APPLICABLE/LIKE_UNKNOWN` (a false positive of the tool) | - |
| candidate matches a documented path template, is the parent of documented paths, or is the specification's URL | not judged (listed in a note) | - |
| calibration unstable; `UPSTREAM_UNAVAILABLE`, `RATE_LIMITED`, `NO_RESPONSE` | `NOT_VERIFIABLE/CALIBRATION_UNSTABLE`, `NOT_VERIFIABLE/<category>` | - |
| the scan completed and no violation | `ENFORCED/NO_UNDOCUMENTED_PATH` | - |
| ffuf failed or timed out (rule 11) | `NOT_VERIFIABLE/TOOL_ERROR` | - |

**`undeclared_methods`** (`0.1`):

| Case | Outcome / detail | Confidence |
|---|---|---|
| same answer as the unsupported-method reference (`METHOD_NOT_ALLOWED` on the expected targets) | `ENFORCED/METHOD_REJECTED` | - |
| any other answer (`SERVED`, `INVALID_REQUEST`, `UNAUTHENTICATED`, `FORBIDDEN`, `NOT_FOUND` on a random identifier when the reference is `405`) | `VIOLATION/UNDECLARED_METHOD_HANDLED` | FIRM |
| `UPSTREAM_UNAVAILABLE`, `RATE_LIMITED`, `NO_RESPONSE`, `SERVER_ERROR` | `NOT_VERIFIABLE/<category>` | - |

**`undocumented_versions`** (`0.1`):

| Case | Outcome / detail | Confidence |
|---|---|---|
| sibling version answers unlike the calibration | `VIOLATION/UNDOCUMENTED_VERSION` | TENTATIVE (the candidate comes from a heuristic rule, topic 5) |
| sibling version answers like an unknown path | `ENFORCED/VERSION_ABSENT` | - |
| no documented path with a version segment | `NOT_APPLICABLE/NO_VERSIONED_PATH` | - |
| calibration unstable, unavailable, no response | `NOT_VERIFIABLE/...` | - |

**`gateway_route_drift`** (`0.1`):

| Case | Outcome / detail | Confidence |
|---|---|---|
| an enabled route under which no documented path and not the specification's URL falls (prefix, exact or regular-expression route) | `VIOLATION/ROUTE_NOT_DOCUMENTED` | CERTAIN (the configuration read) |
| an enabled route with documented paths under it | `ENFORCED/ROUTE_DOCUMENTED` | - |
| a disabled route | `NOT_APPLICABLE/ROUTE_DISABLED` | - |
| no gateway configured | `NOT_APPLICABLE/NO_GATEWAY` | - |
| routes not readable | `NOT_VERIFIABLE/ROUTES_NOT_READABLE` | - |

## 8. Findings

One finding per undocumented path, per undeclared method handled (path and method), per undocumented version, per
route without documentation; each with `evidence_ref` (the request the test sent, or the routes concept read) and
`supporting_refs` (the calibration). Titles: "Undocumented path answers", "Undeclared method handled", "Undocumented
API version answers", "Gateway route without documented paths".

## 9. Effects on the target

- `ext.0.1.ffuf`: `STRESSES_TARGET` (thousands of requests at `requests_per_second`), read-only (`GET`).
- `0.1`: `CHANGES_DATA`: undeclared write methods are sent (owner, 2026-10-21: more discovery is better), on random
  identifiers that do not exist, on the `path_seed` resources, and with an empty body on paths without parameters;
  what they create is deleted where possible or stated as left.

## 10. Per gateway

- Other gateways: `gateway_route_drift` `NOT_APPLICABLE` until an adapter reads their routes; the other sub-tests do
  not depend on the gateway.

## 13. Remediation

Document the endpoint, method or version in the specification, or remove it; remove gateway routes nothing
documented uses; publish only the specification the clients need.

## 14. Limitations

Fuzzing finds what the lists contain; a service that answers every unauthenticated request the same way (crAPI's
identity: 401 to any path) hides its paths from an unauthenticated search, and ffuf is never given credentials (it
does not verify TLS certificates); ffuf's own requests are not TLS-verified (the run's TLS check and the
re-verification of every candidate are);  endpoints known only to a front end (JavaScript) need a crawler (katana,
step 3); a path that answers exactly like an unknown one is not found; `undocumented_versions` tries the neighbours
of the documented versions, not every name a version could have.

**Self-review after the first runs (2026-10-21/22), two weaknesses of the design found and fixed:**

1. **A PASS claimed more than was verified.** The calibration is measured when a test needs it (topics 1-2) and
   shared for the whole run; on crAPI no candidate reached a judgement, so no point was measured and the sub-test
   said PASS **complete** while nothing had been verified: crAPI's identity service answers 401 to any path, so
   ffuf filtered everything as "not found". Fixed: every base path searched is calibrated before its result is
   trusted; one that refuses an unknown path (401, 403) is `NOT_VERIFIABLE/SEARCH_BLIND`, and `ENFORCED` is
   recorded only when at least one base path could tell. crAPI now reads PASS partial with two blind prefixes.
2. **A version group of POST paths was skipped.** The version sub-test lent only `GET` paths, so crAPI's
   `/identity/api/auth/` group (every path a `POST`) was `NOT_APPLICABLE`. Fixed: a `GET` path first, any
   documented method otherwise, with an empty body; crAPI now probes 6 candidates instead of 4, `check-otp`
   included. (The methodology's crAPI case, challenge 3, is a **documented** older version: that is 2.4's
   question, not 0.1's.)

3. **The same blindness in the methods sub-test** (found 2026-10-22 answering the owner's question "are we sure it
   is right?"): all 47 cases crAPI's identity service produced were counted `ENFORCED/METHOD_NOT_SERVED` while both
   the probe and its calibration answered 401, which says nothing about the method. Fixed: when the calibration's
   own answer is a refusal (401, 403), an identical answer is `NOT_VERIFIABLE/REFUSED_BEFORE_ROUTING`. crAPI now
   reads 107 enforced and 48 not verifiable; Forgejo's `undeclared_methods` becomes PASS partial (one such path).
   The three fixes are one rule: an answer that refuses the request proves nothing about what is behind it.

4. **Gateway syntax inside a test** (found 2026-10-22 answering the owner's question on genericity): the route
   comparison read Kong's `~<expression>` and APISIX's `<path>*` itself, which is gateway knowledge in a test.
   Fixed: the `routes` concept carries `RoutePath(value, match)` with `RouteMatch` PREFIX, EXACT or REGEX, each
   adapter translating its own syntax; the test compares without knowing the gateway, and a new gateway needs only
   its adapter. The change also exposed an inconsistency between the two tests of the guarantee: APISIX's exact
   `/api` beside `/api/*` was reported, while ext.0.1.ffuf treats a parent of documented paths as not a finding;
   an exact route path is now covered by the operations under it too. All three labs report one route violation.
